ZMem should compete on benchmark accuracy, latency, token efficiency, and proof-backed reproducibility. The current benchmark harness is designed for internal development and honest public evidence, not unsupported leaderboard claims.

## Official LoCoMo FTS Baseline

The first full LoCoMo FTS run is recorded under `.zerker/bench/locomo-official-v1/fts/`.

- Questions: `1,986`
- F1: `0.3752394031509457`
- EM: `0.37210473313192344`
- Retrieval mode: `fts`
- Trace SHA: `67a005bf87b4bafcd2d7ce1cf8bfff97d7f430788afd0472511f738594971d0c`

Per category:

- Single-hop: `0.6049` F1 / `0.6005` EM
- Multi-hop: `0.0758` F1 / `0.0709` EM
- Temporal: `0.6293` F1 / `0.6293` EM
- Open-domain: `0.1369` F1 / `0.1250` EM
- Adversarial abstention: `0.0` F1 / `0.0` EM

This result says retrieval depth is the immediate bottleneck. The next runs compare multihop decomposition against reranking on the same dataset.

## Next LoCoMo Runs

Run the same dataset through stronger modes with `bench matrix --mode`. This keeps the run shape comparable to the FTS baseline while writing matrix comparison artifacts.

Run multihop first:

```bash
zmem bench matrix locomo \
  --dataset data/locomo/locomo_official_zmem.json \
  --out .zerker/bench \
  --run-id locomo-official-v1 \
  --mode fts-multihop \
  --seed 42
```

Then run dense/rerank modes:

```bash
zmem bench matrix locomo \
  --dataset data/locomo/locomo_official_zmem.json \
  --out .zerker/bench \
  --run-id locomo-official-v1 \
  --mode pseudo-embedding \
  --seed 42

zmem bench matrix locomo \
  --dataset data/locomo/locomo_official_zmem.json \
  --out .zerker/bench \
  --run-id locomo-official-v1 \
  --mode pseudo-embedding-rerank \
  --seed 42

zmem bench matrix locomo \
  --dataset data/locomo/locomo_official_zmem.json \
  --out .zerker/bench \
  --run-id locomo-official-v1 \
  --mode zmem-retrieval \
  --seed 42
```

Why this order:

- `fts-multihop` tests whether query decomposition moves the weakest multi-hop and open-domain categories.
- `pseudo-embedding` separates dense recall from reranking.
- `pseudo-embedding-rerank` tests whether reranking improves retrieval depth against the same fixed dataset and seed.
- `zmem-retrieval` is the stable alias for the strongest current local retrieval mode. It currently resolves to the concrete rerank mode in the stored result.
- The same `--out`, `--seed`, and dataset keep the comparison clean.

Render and verify after the modes finish:

```bash
zmem bench report .zerker/bench/locomo-official-v1 --summary-only
zmem bench dashboard .zerker/bench/locomo-official-v1
zmem bench public-page .zerker/bench/locomo-official-v1
zmem bench verify .zerker/bench/locomo-official-v1/benchmark-matrix.json --summary-only
```

## Category Deltas

The harness already writes per-category summaries and comparison rows. Use the rendered report/dashboard to answer:

- does `fts-multihop` improve multi-hop,
- does it preserve temporal,
- does rerank improve open-domain,
- does any mode improve adversarial abstention.

There is not a category-filter CLI yet. If full runs are too expensive, add category filtering before running many category-only sweeps.

## Token Budget Sweep

Use the same mode and dataset at a few budgets to separate "retrieval found the wrong thing" from "retrieval found the right thing but packing dropped it."

```bash
zmem bench matrix locomo \
  --dataset data/locomo/locomo_official_zmem.json \
  --out .zerker/bench \
  --run-id locomo-official-v1-budget-384 \
  --mode fts-multihop \
  --seed 42 \
  --context-budget-tokens 384

zmem bench matrix locomo \
  --dataset data/locomo/locomo_official_zmem.json \
  --out .zerker/bench \
  --run-id locomo-official-v1-budget-768 \
  --mode fts-multihop \
  --seed 42 \
  --context-budget-tokens 768
```

Add the same sweep for `pseudo-embedding-rerank` only if multihop shows signal or budget-dropped context appears in the reports.

## ActiveGraph Compact Trace

Use ActiveGraph for storage-safe trace runs and use-case proof. It writes `trace.jsonl` and `scored_receipt.json` instead of per-question receipt bundles.

Smoke first:

```bash
zmem-bench-locomo \
  --dataset data/locomo/locomo_official_zmem.json \
  --out .zerker/bench/activegraph-locomo-smoke \
  --run-id activegraph-smoke-fts-multihop \
  --retrieval-mode fts-multihop \
  --split default \
  --limit 5
```

Then use it for longer compact traces after the standard matrix identifies the modes worth preserving.

## Frontier Queue

Next benchmark priorities:

- LongMemEval-S: abstention and token-efficiency benchmark.
- LoCoMo `fts-multihop`: decomposition delta against the recorded FTS baseline.
- LoCoMo `pseudo-embedding`: dense-recall delta against the same baseline.
- LoCoMo `pseudo-embedding-rerank`: reranking delta against the same baseline.
- BEAM: scale benchmark for 100K to 10M token memory pressure and causal traces.

Fast product fix to test:

- Add a deterministic abstention path when retrieved memory is empty or confidence is below threshold.
- Verify it against LoCoMo adversarial abstention and LongMemEval-S.

## Public Claim Rules

Allowed before official submissions:

- "ZMem publishes proof-backed local benchmark evidence."
- "This matrix is reproducible from the attached artifact hashes and receipts."
- "This local scaffold tracks retrieval accuracy, latency, tokens, and proof verification."

Do not claim official LongMemEval or LoCoMo ranking, vendor superiority, or canonical leaderboard score from local scaffold output.

## What To Track

- accuracy and category accuracy,
- recall and precision evidence where ground-truth support exists,
- p50, p95, and p99 retrieval latency,
- total tokens and injected context tokens,
- retrieved, injected, withheld, and budget-dropped memory counts,
- verification status,
- matrix hash and comparison hash,
- optional Treeship proof URL when public proof publishing is enabled.
