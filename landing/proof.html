Product Matrix

ZMem is agent-native local memory: agents can ask, learn, act, explain, and hand off without turning memory into an opaque context blob.

Local memory coreTyped memory that stays local and inspectable.
Gives agents durable memory without shipping state to a hosted memory service.
SQLite, FTS search, typed records, lifecycle states, source, scope, trust, authority.

Keeps self-generated memory from becoming authority by default.

Kept Honest

The launch page should be strong without pretending the future is already shipped.

Standalone first

ZMem works locally without Treeship. Treeship is the optional proof-publication layer when a public receipt is useful.

Alpha boundary

The local memory loop is functional. Hosted team review, enterprise control plane features, and public package release are not claimed as done.

Launch gate

Strict publish remains blocked until the clean-shell proof logs and launch screenshots/GIFs exist.

Verified Commands

These examples match the current CLI help surface and release-smoke contract.

Start local 
curl -fsSL https://raw.githubusercontent.com/zerkerlabs/zmem/main/install.sh | bash
zmem status --summary-only
zmem ui
Connect agents 
zmem agent install codex
zmem agent install claude-code
zmem agent install cursor --summary-only
zmem agent pack --summary-only
zmem agent mcp-smoke --agent codex
Handoff and proof 
zmem handoff --summary-only
zmem --db .zerker/imported.sqlite restore --handoff-dir .zerker/handoff
zmem verify <action-id>
zmem treeship publish <action-id>
Bridge chats 
zmem propose "Cross-chat checkpoint: ..." --type episodic --scope project --source agent --label cross-chat-checkpoint
zmem queue --scope project --status quarantined
zmem promote <memory-id>
zmem inject "continue the task" --agent codex --scope project --risk medium
Benchmarks and release 
zmem bench list
zmem bench matrix synthetic --out .zerker/bench/synthetic-matrix
zmem release-pack --summary-only
zmem prelaunch --summary-only

Release Plan

The launch plan is intentionally small: publish only after the proof artifacts say the public install path and final assets are real.

1. Keep local alpha green

Run release smoke, keep status ready, keep operator packet ready, and keep examples aligned with CLI help.

2. Prove public install

Use the clean-shell operator packet to capture 6 logs, including raw curl install and packaged release smoke.

3. Capture launch assets

Save 8 screenshots/GIFs under .zerker/launch-proof/assets/, then run zmem verify-launch-assets --summary-only.

4. Accept return packet

Finalize the return packet and accept it only when zmem verify-return-packet ... --summary-only reports ready.
